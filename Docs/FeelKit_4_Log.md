**Controller rumble: root cause found and fixed (2026-09-17, night)**
- **User:** "I was able to finally plug in the controller correctly and it still wouldn't vibrate. So it's definitely something in the code."
- **Root cause (I-029, I-032):** two things stacked.
  1. `showdebug forcefeedback`'s "Current Playing Force Feedback" line shows each effect's **own** values, **before** the player controller's `ForceFeedbackScale` (engine `PlayerController.cpp:3398` lists effects, the scale is applied at 4731-4735 and only appears in the earlier "Force Feedback - Enabled:" line). Both of the user's screenshots showed the per-effect lines, so "the values move" never proved anything reached the device.
  2. FeelKit set `PlayerController->ForceFeedbackScale = Master x Haptics` (setting **Apply Comfort To Engine Force Feedback**, on by default), overwriting the game's own value. With Haptics comfort 0 **all** vibration in the game stops, including effects FeelKit knows nothing about, with nothing on screen saying so. The user's Blueprint sets Haptics comfort to 0 on the **H key** (the duplicate node, I-028) - the very key the checklist used to test the engine's force feedback, so every test silenced the pad first.
- **Proof (`DiagFeel.PIEForceFeedback`, extended to repeat the user's sequence):** clean session engine 0.99 / FeelKit 0.99; after Haptics comfort 0: `forceFeedbackScale=0.00`, **what showdebug lists per effect = 1.00, what actually reaches the controller = 0.00**; after comfort 1 the scale returns to 1.00.
- **Fix (D-046):** `UFeelComfortSubsystem` now remembers the scale the game set, applies comfort as a **multiplier** on it, writes only its own value back, and restores the game's value when the controller changes, when the setting is turned off, or when the subsystem shuts down. - **User:** "The demo is crazy good nice work. The only issue are these warnings." Three PIE warnings "Attempting to move a fully simulated skeletal mesh ... BP_CombatEnemy_C_n.CharacterMesh0. Please use the Teleport flag".

Check via `UPrimitiveComponent::IsSimulatingPhysics` (Engine only; the body instance call lives in PhysicsCore, which FeelCore must not use, hard rule 3). Scale and material effects are unchanged. Assumption: a skeletal mesh in "component transform is kinematic" mode reports not simulating and is still moved; not used by the templates.

### T-2 findings (2026-09-16, summary)
- **Core finding:** in the games studied, feedback is a response to an event, selected by context and scaled by game state (Sekiro deflect vs block, Balatro shake tiers, Monster Hunter hitstop per weapon, Hollow Knight i-frame muffle, Dead Space intensity director). FeelKit has the response half only: no Parameters on `UFeelRecipe` (Strategy 2.3 asked to reserve it; not done), no context on `FFeelTarget`, no sustained/looping recipes, Conditions not evaluated (I-006).
- **Position proposed:** FeelKit is the response layer: gameplay sends a tag plus context; FeelKit chooses variant, strength, order across all channels, comfort-safe and scrubbable.
- **OWN:** Parameters + Play Context (first, structural); Feel Events + Feel Map (tag + context tags → recipe, most-specific wins) with anim notify/state and trigger component; escalation accumulators; sustained recipes; sensory steps (particles, screen color, audio mix, overlay hit-flash, light flash, decal, nested/random) without content libraries; thin UI steps + number pop; moment capture; flash limiter + sensory substitution; priority culling; networking (thin).
- **INTEGRATE:** GAS cue adapter, Enhanced Input, Wwise/FMOD event steps, advanced haptics adapters, Rewind Debugger track, Gameplay Cameras compatibility, Quartz beat quantize (later).
- **AVOID:** hit reactions/animation, VFX/SFX libraries, damage/combat systems, camera rigs, settings menus, telemetry, audio-to-haptic synthesis, recipe marketplace, generic event bus, beat-synced timelines.
- **Demo-derived priority:** Parameters (5/5 demos), Context (4), Events/triggers (4), Escalation (4), UI steps (4), Number Pop (4), Particles (4), Screen Color (4), Sustained (3, blocks Horror entirely). Networking and beat sync: 0.
- **Open questions:** Fab rules for shipping template-derived or licensed audio content; Gameplay Cameras compatibility with our camera modifier in 5.7/5.8; loop-aware side effects in sustained recipes; asymmetric targets API shape; OverlayMaterial conflicts.

### T-1 findings (2026-09-16, summary; full evidence and sources in the report)
**Verdict: not yet meaningfully ahead as a product.** Ahead on editor workflow, not on what a Fab buyer compares first.
- **Ahead:** timeline authoring (no Unreal competitor has one); preview without PIE (no Unreal juice plugin); cross-channel arbiters; per-player comfort layer (competitors offer at best a global intensity or kill switch).
- **Parity:** audio, performance claims, Blueprint-extensible steps. Preview is commoditising: More Mountains Feel (Unity) added an experimental preview mode in July 2026; Sparkle (Godot) has one.
- **Behind:** step count (~15 vs Game Juice Pro 28 vs Feel 150+); randomization and distance falloff; triggers (anim notify, damage, GAS cues); networking; content, presets, demos, docs; engine version range (GJP supports UE 5.3 to 5.8, we are 5.6+); price; community.
- **Main threat:** Game Juice Pro ($29.99, 5.0 from 6 ratings, UE 5.3 to 5.8): Feel-style runtime plus multiplayer; its first review positions it as "Feel for Unreal", the slot FeelKit wants.
- **Top gaps:** (1) randomization / chance / distance falloff (and I-006 dead Conditions); (2) triggers; (3) networking; (4) breadth, content, persistent/looping states (e.g. low-health vignette); (5) comfort compliance (I-007) and comfort not reaching engine-native shakes.
- **Top differentiator candidates:** (1) moment capture: record recent plays in PIE, scrub the exact hit in the timeline with arbiter decisions shown (pure evaluation makes this cheap; timer/spring-based competitors cannot easily copy); (2) certifiable comfort: scale engine-native shakes and force feedback, audit report mapped to Xbox camera comfort guideline; (3) recipe parameters with live preview sliders and draggable distance falloff; (4) audio-driven authoring (waveform, transient snapping, audio-to-shake/haptics); (5) Off/On GIF/MP4 capture; MCP tools for UE 5.8 (medium, Epic marks MCP experimental).
- **Strategic flags for user decision:** price ($70-80 hard in a $15-40 category; suggestion ~$39.99 core + studio tier); name/prefix still unresolved and Fab search favours "juice"/"hitstop" terms over "feel".
- **Unverified:** Agentic FeedbackFX personal license price (listing vs site conflict); Game Juice Pro having no editor preview (install to confirm).
